## 0. 摘要

Sorne 是一个**能跑通、门禁全绿**的 dsh 插件形态持续探索型渗透测试 Agent：单 SQLite 库 + 受控串行事务 + Outbox 事件流 + 四角色（Planner/Orchestrator/Worker/Verifier）LLM 循环 + 9 页 React 无构建前端。蓝图 44 个端点全部实装；迁移 0001–0011 可干净应用到 schema_version=11（52 表/33 索引）；`npm test` 实测 **604 tests / 603 pass / 0 fail / 1 skipped（真实模型用例）**，退出码 0。

代码对「证据不可变、提交幂等、租约围栏、发现者不自证、delivered≠applied、只读投影不成为第二真值源」等核心不变量有**真实实现与故障注入测试**，不是纸面设计。但精读发现 **3 个 P0 级缺陷**（1 个已由 Lead 逐行复核）与约 **30 个 P1 级语义/安全/可用性缺陷**，集中在三处：跨模块拼装处（同一语义多套实现）、关键旁路（绕过唯一状态机/唯一校验）、以及真实宿主与真实 React 下才暴露的前端路径。

## 2. 总体架构

### 2.1 运行形态

`index.js:apply(ctx)` 在 dsh 宿主进程内同步注册 `/sorne` 前缀路由（`webServer.register({kind:"prefix"})`）、异步装载路由文件、启动 Agent 运行时（无 LLM 配置时显式 `started:false` 等待）、注册 6 个只读 dsh 工具；`ctx.effect` 在卸载时反注册路由并 stop 运行时。数据根默认 `~/.sorne`（`SORNE_DATA_DIR` 覆盖），单库 `<dataDir>/state/sorne.sqlite` + 项目文件树（assets/maps/reports/work/evidence）。

### 2.2 传输层（`lib/http.mjs` + `lib/router.mjs`）

分发顺序是**信任先于路由**：非回环或携带 `Forwarded/X-Forwarded-*/*X-Real-IP` → 403（未知路径也 403，不泄露路由存在性）→ 路由匹配 → 变更请求同源 Origin 校验（回环机器第二道）→ JSON 体预读（256 KiB；`rawBody` 路由不预读，供证据字节流式上传）→ handler。handler 返回非 `undefined` 自动 200 JSON；`ApiError` 统一错误信封；其他异常 500 INTERNAL_ERROR。`lib/errors.mjs` 固化 §20.1 的 13 个业务码 + 6 个传输/桩码。

### 2.3 存储底座（`lib/db.mjs`）

`node:sqlite`（DatabaseSync），WAL + `foreign_keys=ON` + `busy_timeout=5000`；迁移逐版本在 `BEGIN IMMEDIATE` 内「事务内复查版本 → up → 写 schema_version」；所有写入经 `runSerial(fn)` 串行短事务（事务体必须同步，不得 await）。`commit_seq` 为项目级单调提交序（`projects.next_commit_seq`），业务行与 Outbox 事件同事务；稳定编号由 `id_sequences` 分配，存在「全局格式族 `A-0001`」与「项目内嵌族 `A-PRJ-0002-0001`」两套并存（0004 迁移只把前者收口到 `_global`）。

### 2.5 AI 运行时（`lib/agents`）

`runtime.tick()` 默认 5s 一轮、每项目顺序 `runOnce`：租约清扫 → 工作面快照（9 项计数）→ 唤醒判定（active/waiting_for_change）→ 队列准入（proposed≤8）→ Orchestrator（信号指纹 + 5 分钟冷却，单飞）→ Planner（有在途 plan_run 时）→ Worker（leased/running≤4，每 Attempt 每进程只驱动一次）→ Verifier（pending/in_progress≤4）→ Outbox 消费回执。四角色均为独立系统提示 + 工具面 + 程序签发会话（`issueSession`），模型客户端走 OpenAI 兼容 `/chat/completions`（429 退避、120s 超时），无提供方时显式等待、不伪造决策。

### 2.6 前端（`client.js` + `lib/ui`）

`client.js` 经 `window.__ModuleLoader__` 注册、向 `settings.section` 注入 SornePanel；启动时取 `/sorne/ui/manifest` 动态 import 9 个页面模块（无构建、纯 ESM、零 import、React 由外壳注入）；hash 路由 + 返回栈；详情右栏槽位；记录覆盖层；keep-alive 页面缓存；24 颜色 token × 明暗双主题；`lib/ui/render.mjs` 统一渲染器与词表；`record-ids.mjs` 全站唯一编号正则。

## 3. 数据模型与核心不变量

- **52 张表/33 个显式索引**（0001 冻结全量 + 0002–0011 演进），`PRAGMA foreign_key_check` 0 违规；0002 把 submissions 改为 `(project_id,submitter_id,id)` 身份域主键；0003 意图状态历史；0004 全局编号序列抬基线；0005 messages；0006 projects.task；0007 主动阅读；0008 批量提取；0009 覆盖/修正；0010 分支摘要；0011 分支搁置。
- **不可变证据**：Blob 内容寻址（`UNIQUE(project_id,sha256)`），写入顺序 staging→SHA-256→固定路径→库事务登记→回执；同内容只留一份、采集历史不删；读取每次核哈希。
- **幂等提交**：同一 `(project_id, submitter_id, submission_id)` + 请求摘要 → 原回执；同 ID 不同内容 → `IDEMPOTENCY_KEY_REUSED`。
- **租约/围栏**：部分唯一索引 `UNIQUE(project_id,assignment_id) WHERE status IN ('leased','running')` + 项目内单调 fencing token；所有执行动作前校验活租约。
- **版本竞争**：判断类三版本（`claim_revision/evidence_revision/assessment_epoch`）+ `state_version`；D1 核心事务在事务内比对期望版本，不匹配走 stale 分支并用**带回执的错误**返回。
- **范围三态**：deny 优先 → 显式 pending → allow → 未列出=pending；派发/工具登记/启动/完成四道闸门。
- **事件与回执**：Outbox `UNIQUE(project_id,commit_seq,event_index)`；`consumer_receipts` 用 `delivered` 与 `applied` 分存表达 delivered≠applied。
- **投影只读**：快照只读业务表、不写 subscriptions（订阅边界由 changes 的冻结签名建立）、文件先原子落盘再落行，可完全重建。

## 4. 十条核心数据流（精读结论）

1. **幂等提交（#10）**：简历封 → 形状/操作预检（不进事务）→ 身份域幂等 → commit_seq → 操作 handler（校验→写行→emit）→ Outbox → submissions 回执。
2. **证据上传/采集（#11/#12）**：rawBody 流式 staging → 哈希固定 → 事务登记 Blob → 回执；Capture 以 tool_call_id 幂等、登记后同事务发 `capture.completed`。
3. **Map 快照（#13/#15）**：B2 建订阅边界 S → 同步一致读 content（commit_seq<S）→ 分配 SNAP 号 → 写文件 → 落 snapshots 行 → 返回订阅四元组。
4. **记录读取（#14）**：编号前缀→物理表定位（40+ 表视图、双前缀族、未知前缀兜底全表）→ 视图 + 证据索引 + 1 跳关系边；跨项目/不存在统一 404。
5. **主动阅读（/reading/*）**：虚拟节点树（root/assets/goals/...）+ 游标分页 + 搜索 + 关系跳转 + 证据片段（真实字节范围 + 材料读取日志）+ 隔离书签。
6. **计划接收（#20）**：planner 信封 → 范围/前提/依赖环校验 → 意图九态 + 历史 → plan_revision/run → 事件；修订走乐观锁并只挂起受影响部分。
7. **派发与网关（#22/#26）**：sweep → 范围/前提/上限 → 条件领取 + fencing → 工具 planned→running→succeeded/failed/unknown；unknown 未 resolve 不得同身份重试。
8. **验证与状态机（#27/#28）**：请求生成不可变 Manifest + 三版本期望 → verifier 提交结果 → 事务内校验独立性/版本/检查项 → `applyStateTransition`（D2 唯一状态机）→ 同事务 Outbox；竞争分支带回执报错。
9. **协调与规划（#31–#36）**：Orchestrator 面板 + 用户消息 → submit_decision → 决定/动作持久化（幂等）→ 逐动作核对实际效果后委托 C2/C1/D1 执行；Planner 由在途 plan_run 触发并提交新计划修订。
10. **报告/恢复（#39–#42）**：报告视图在一致读内按漏洞指纹同步版本（文件先行→落行）；恢复七步真实关库重启后产出清单但不自动派发；Outbox 变化页/回执驱动长期运行。

## 8. 测试质量评估

**基线**：`npm test` 实测 604 tests / 603 pass / 0 fail / 1 skip（唯一真实模型用例默认跳过，需 `SORNE_REALRUN=1` + llm.json），退出码 0，测试段耗时约 5.4s。

**优点**：绝大多数用例是真实 `apply()` + 随机端口 + 临时数据目录 + 真实 SQLite；故障注入用真实 `closeStore/server.close` 重启与 SQLite `TRIGGER RAISE(ABORT)`；竞争/越权/幂等断言读库侧状态；changes 用“分页并集=全量”防漏事件；UI 用自建迷你渲染器而非 golden HTML。

**问题（15 分片汇总）**：
- **把缺陷写成期望**：agents 用例全部显式调 `store_evidence`，从不校验 `register_tool_call` 回执是否含 evidence → 掩盖 P0-1；修 P0-1 会同时撞红 `agents-realrun:279-280` 与 `agents.test:225/554`（回执形状变化），需同步改测。

### 8.1 测试「假绿/固化」清单（15 分片交叉证据）

1. **P0-1 被测试绕开**：所有 Worker 用例显式调 `store_evidence`（agents.test:217/551；agents-realrun:279/344/386/418），没有任何用例断言 `register_tool_call` 回执必含 evidence；修复 P0-1 反而会使 `agents-realrun:279-280` 与 `agents.test:225/554` 变红（回执形状/表示形式变化），修码与改测必须同批。
2. **publishRefresh 恒 stale 被三处写死**：`stage5:107` 用 `["current","stale"]` 二选一放行 → `stage7:343` 直接硬断言 stale → `fix-reachability:258-261` 与 `fix-deepening:129-131` 必须先手工 UPDATE 成 current 才能继续测后续行为。
3. **复刻实现缺陷**：`reports.test.mjs:251` 原样复制实现的 `ORDER BY CAST(version AS INTEGER)`（对 'vN' 恒 0、排序退化为 rowid），随后按 `rows[0]` 取 v1，版本序缺陷在测试内被复刻而不可见。
4. **过期规避**：`worker-reports.test.mjs:945-947`、`reports.test.mjs:782-783` 用 `withScope:false` 规避“A1 createProject SR 跨项目主键冲突”，但 0004 迁移已把 SR 收口到 `_global` 序列——注释过期，第二项目带初始范围的路径长期无覆盖。
5. **stage7 多处假绿**：`:540` 用 `r.text?.includes(...)` 判跨项目泄露，但 `briefNode` 无 `text` 字段 → 恒 false；`:438` `wakeBefore` 死变量；`:58` 范围规则写成 `{pattern:"*.webapp.local"}`，`matchScopeRule` 只认 host/scheme/port/path_prefix → 全程未触发范围闸门；`:362` “崩溃”没有进程退出/句柄关闭/重启。
6. **UI 测试替身比生产宽**：onboarding/projects/reports 三组 `fake apiError` 都额外挂 `e.body/e.detail`，生产 `client.js api()` 只保留 message/code → next_requirements/detail.note/INTERNAL_ERROR 断言在真实浏览器必不成立；mock router 不建模 projectId → 引导层 chip 丢项目参数的缺陷不可见；reports 手写 ~300 行 #39/#40 fixture 自证，真实端点漂移不会红。

8. **隔离/执行瑕疵**：`test/helpers.mjs:42` 的 `effect:(fn)=>fn()` 丢弃 disposer → `agents.stop()/dshBridge.dispose()` 永不执行、5s ticker 残留；`outbox-consumer.test.mjs:58` 误用 evidence 的 `closeAllStores`；`stage7:362` 的“重启”只读一次 recoverContext；测试宿主若外部设 `SORNE_DATA_DIR` 会写真实目录。

> 结论：测试规模与真实注入手段在同类项目里属上游水平，但**回归网对最危险的几个缺陷恰好失明**，且修复缺陷会先撞红“把缺陷当期望”的用例。整改顺序应是「先补一条会红的负例 → 再修实现 → 再改既有期望」，而不是直接改实现。

## 9. 结论与建议（阅读结论，未执行修改）

1. **先修 P0**：把 `autoFixEvidence` 提到模块作用域并让 catch 记录失败（同步修改上述两处测试与 store_evidence 回执形状断言）；`matchScopeRule` 对象分支加路径边界（`path===prefix || startsWith(prefix+"/")`）并补 `/api` vs `/api-secret` 负例；就“真实宿主如何服务 `/sorne/ui/lib`”做架构裁决（若不可行，内联设计系统模块或扩 UI 路由，需走冻结文件变更流程）。
