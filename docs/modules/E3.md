## 2. 实现范围

- 端点（蓝图 §5 注册表编号）：本页为纯消费端，无自有端点。数据来源：#31 GET
  /orchestrator/overview（E1）、#38 GET /worker-reports/{id}（E2，按层 layer=
  handoff_card / key_records / full_basis）、#4 GET /projects（A1，项目选择器，
  同 A3/B3/C3/D3 模式）、#14 GET /records/{id}（B1，编号展开）；E2 落地信封的
  read_pointer 另含 #44 GET /captures/{id} 与 #43 GET /evidence/blobs/{sha256}
  （A2），页面按返回的入口原样读取（只读展示）。
- 表/迁移（蓝图 §4）：无（纯前端页，不触碰任何表与迁移）。
- 事件（蓝图 §6 目录）：无。
- 错误码（蓝图 §5.3）：无新增；消费面呈现 E1/E2/B1 回传的 NOT_FOUND/INTERNAL_ERROR/
  TRUST_DENIED/BAD_REQUEST 等既有码。
- 页面结构（§18.6 工作面板 + §18.3 三层展开）：
  - **项目选择**（#4）：游标分页累积、自动选择首个项目、切换项目以新 project_id 重读；
  - **工作面板（§18.6 六要素，#31）**：活跃计划 / 各意图最新状态 / 未处理汇报 /
    重要新发现 / 待决事项 / 关键限制六个区块一一对应，各自独立多来源提取——E1
    落地信封（对象嵌套形态：active_plan.latest_plan_revisions、intents.active +
    counts_by_status、pending_reports.items、important_findings.{vulnerabilities,
    hypotheses}、pending_items.interrupted_actions.items、constraints）优先命中，
    数组键防御形态兼容；区块未提供显式呈现（未提供 ≠ 不存在，§15.4 精神），
    has_more 不完整提示，数据时刻标注；未处理汇报按 handling_status ≠ handled
    呈现（delivered ≠ 处理，§18.5）；
  - **汇报分层展开（§18.3 三层，#38）**：交接卡层默认接收（E2 分组形态：分组
    逐组呈现、按长度预算分页续读、omitted_from_this_page 显式列明不静默截断；
    扁平防御形态兼容：顶层 + DDL TEXT content JSON 双路提取）；关键记录层默认
    收起、按需请求 layer=key_records（发现清单含 E2 的 db 状态注记「提交时声明
    vs 库内当前」、advice 对象的「AI 建议单独标注」、遗漏分区读取入口、
    expand_pointer）；完整依据层默认收起、核查时请求 layer=full_basis
    （evidence_refs 对象带 read_pointer 原样展示、manifest 渲染、note）；
  - **基线读取链（§18.6）**：base_report_id / replaces_report_id 可点击读取；
    relative_to_base（E2 落地：新增/移除/未变编号集合）渲染且「读取基线」直达
    基线 key_records 层；下钻链显示并可返回上一份（不依赖对话记忆）；
  - **读取入口路由**：/sorne/worker-reports/{id}?layer=… 直达对应层（本汇报的
    expand_pointer 与他汇报的 base_read_pointer/遗漏分区入口按 id 归属区分是否
    记入下钻链）；其余 /sorne/* 入口原样读取（#14/#44/#43）；WR- 编号走 #38，
    其余编号走 #14；
  - **按编号展开记录（#14）**：发现/证据引用/待决关联/文本中的编号可点击展开，
    空输入本地拦截；结果只读展示（对象=分组、数组=清单、深层级退化为原始 JSON）；
  - **接收端语义说明**（§18.6/§18.3/§18.5/§18.4 静态文案全量在场）；
  - 501 → 「未实现」标注负责模块、错误 → 错误卡（TRUST_DENIED 附会话缺口说明）、
    未知形状 → 显式提示、空态显式；全中文文案、不夸大状态；不使用任何浏览器存储。
