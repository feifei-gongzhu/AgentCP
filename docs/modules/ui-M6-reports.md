## 2. 实现范围

- 端点（消费，无新增）：
  - #39 `GET /sorne/reports/vulnerabilities?project_id=&cursor=&id=&version=`
    —— 摘要列表（cursor 分页）+ 单份详情（当前/历史版本）；
  - #40 `GET /sorne/reports/milestones?project_id=&version=&refresh=1`
    —— 单份阶段报告（五分区 + coverage 覆盖块）；读取默认不增殖版本，refresh=1 显式生成；
  - #14 `GET /sorne/records/{id}?project_id=` —— 详情先按 RR-/MR- 报告版本编号解析
    report_revisions 行（report_kind / subject_id / version），再读 #39/#40；
  - #53 `GET /sorne/reports/{id}/export?project_id=&version=` —— Markdown 导出（下载链接，
    失败如实 404 + note + 下一步）。
- 表/迁移：无（报告是派生资料；页面只读，不写库、不发事件）。
- 事件：无。
- 错误码呈现：错误信封 `{code,message,retryable,next_requirements,detail}` 原样呈现
  （`code · message`，优先 message）；501 `NOT_IMPLEMENTED` 呈现为「未实现（不是报错）」
  并标注负责模块（若信封携带）；404 不泄露存在性且给下一步条件。

### 实现要点（对照施工要求逐条）

- **页面注册表**：`id="reports"`, `title="报告"`, `order=60`（BLUEPRINT-UI §2.5 冻结值；
  旧页的 title="报告与覆盖度"/order=90 已按新契约更新——旧断言迁移见 §5）。
- **项目上下文**：项目一律取自 `router.projectId`（#/p/:pid/reports），**页面不再有项目
  选择器**（§1.1/§2.4：切页不重新选项目；所有取数带 project_id）。
- **漏洞报告区**：#39 摘要表（列：漏洞编号 chip / 状态徽章 / 复核状态徽章 / 当前版本 /
  版本数 / 数据截止边界 / 报告版本编号 chip）；状态与复核分列（词表徽章携带冻结措辞：
  「已确认（限指定条件）」「证据不足：未确认，不伪装成已排除」「已证伪（不等于历史上
  不存在）」）；`next_cursor` + `has_more` 真分页（仅 has_more 时渲染「加载更多」，
  携带 cursor、跨页按 id 累积、结束即消失）；每行点击 → `?id=<report_id>`。
- **阶段报告区**：#40 当前版本卡（版本切换 chips、报告版本编号 chip、数据截止边界、
  五分区计数、进行中探索）；「生成阶段报告（数据截止到当前）」→ 同端点 `refresh=1`
  （生成后提示「本次读取生成了携带最新数据截止边界的新版本（读取默认不增殖版本）」，
  并显式写明「生成报告不结束项目」）；「阅读完整阶段报告」→ 右栏详情。
- **覆盖缺口区**：取 #40 当前版本 `coverage` 块——未覆盖聚合、按资产/测试方向/身份或
  条件记录（四方向 total/resolved/blocked/ongoing/cancelled、采集/观察/直接意图、身份
  条件、未覆盖标记）；`has_more` 时展示 `folded_note`（不静默截断）；覆盖口径说明
  收进折叠区；空态「未提供不代表已覆盖」。
- **单份详情（renderDetail，右侧槽位）**：hash `?id=` 驱动（RR-/MR- 报告版本编号；兼容
  `V-` 主体编号取最新版本）；先经 #14 解析报告版本行，再读 #39/#40；版本切换 chips 通过
  导航到目标版本的 RR/MR 编号（hash 为唯一状态：刷新/分享/回退成立）；历史版本显式提示
  「正在查看历史版本（vN）：历史版本保留供追溯，当前视图以最新版本（vM）为准」，且内容
  与数据截止边界随版本切换。
  - 漏洞详情：§19 最小内容集——状态/复核、判断条件、影响、资产 chip、支持/反对证据
    （成员 chip + 立场/成员状态 + 陈述）、验证结论（VR-/VJ-/EM- chip、outcome 徽章、
    applied「已应用/未应用（保留意见，不覆盖新结论）」、verifier_identity/kind/policy、
    **reviewed_evidence_revision 实际值**）、待处理验证任务、限制原文、来源/后续意图 chip、
    四向追溯（折叠原始结构）、版本元数据与边界。
  - 阶段报告详情：项目 chip、五分区明细（已确认漏洞/事实、未确认线索、已完成/受阻方向
    （含 resume_conditions）、未覆盖）、探索继续说明、边界与版本元数据。
- **导出**：详情页「导出本版本（Markdown）」→ 先 GET #53 检查可导出性并读取内容（真实
  client api 对非 JSON 响应回 `{raw}`），成功呈现 `<a download>` 同源下载链接 + 「内容与
  当前视图同源（服务端确定性渲染，共 N 字符）」；失败呈现「导出失败：code · message」、
  服务端 note（若有）与下一步条件（「内容文件不可读时，可先生成携带最新截止边界的新版本
  后再导出；不虚报导出成功」）。失败时不渲染下载链接。
- **语义纪律与版式**：正文只保留任务导向一句与数据口径；全部解释性规范段落收进
  「语义说明」`FoldableObject` 折叠区（显示「已折叠 7 项」，展开不删记录）；
  **可见正文「§」为 0（≤2/页，蓝图为上限、实现更严）**；服务端返回的解释性 note
  （#39 note、覆盖口径 note）同样折叠，避免数据中的章节引用进入可见正文。
- **设计系统**：页面零 import、无读取渲染自实现——时间/编号/哈希/字段/状态/折叠/空态全部
  经 `ctx.ui`（`formatTime`/`RecordIdChip`/`StatusBadge`/`FieldRow`/`FoldableObject`/
  `EmptyState`）；无字面颜色值、无宿主 `--dsw-alias-*`；正文 13–14px（标题 15–17px）；
  全部按钮 aria-label、编号 chip aria-label 为完整编号；不复制编号、不手抄编号。
- **数据口径**：每个数据面标注「数据时刻（本地化）/ 截止边界（提交边界 + 生成时间）/
  不代表全量 / 按已加载数据推导」；不裸出 UTC ISO 串。

### 新增/重写测试文件与用例清单（test/ui-reports.test.mjs，28 用例）

1. M6 页面契约：纯 ESM 不引包、无编号正则副本、无字面颜色/宿主变量、`title="报告"`、
   `order=60`、render+renderDetail、SEMANTICS 之外零章节引用；

3. 漏洞报告列表：状态/复核分列、版本计数、数据截止边界、报告版本编号 chip、计数口径、
   可见正文「§」为 0、不裸出 UTC ISO；
4. 漏洞报告分页：cursor 携带 + 跨页累积 + 结束按钮消失；
5. 501 未实现：两区「未实现（不是报错）」+ 负责模块 + 语义说明/覆盖区仍在；
6. 错误态：5xx 错误卡（code · message），其余区块不受影响；
7. 未知形状：无 reports/report 键 → 显式「形状无法识别」；
8. 空态：无漏洞报告 + 空阶段报告；分区 0 条为准确计数、覆盖空态不虚构；
9. 阶段报告：数据截止边界 + 生成时间 + 边界之后/不代表全量、五分区计数、版本切换、
   读取默认不增殖；
10. 阶段报告版本切换：历史版本按钮导航到该版本的 MR- 报告编号 hash；
11. 按需生成（refresh=1）：请求携带 refresh、版本推进、如实提示且不结束项目；
12. 覆盖缺口：未覆盖聚合 + 覆盖表（资产/方向/身份条件/未覆盖标记）+ 折叠口径说明；
13. 语义说明折叠区：冻结原文保留（不删记录）、可见正文无章节引用；
14. 详情（?id=RR-）：经 #14 解析后读 #39；§19 最小内容集、reviewed_evidence_revision
    实际值、验证结论/待处理任务、四向追溯、边界；
15. 详情历史版本：显式提示 + 边界同步 + 版本按钮导航到目标 RR- 编号；
16. 详情（?id=MR-）：经 #14 解析后读 #40（version 参数）；五分区明细 + 覆盖记录；
17. 详情以 V- 编号直接打开：按主体读最新版本（兼容链接）；
18. 详情错误态：RR 不存在 404 如实呈现；无法识别编号显式拒绝（不猜测）；
19. 列表行点击导航 hash；编号 chip → `openRecord` 完整编号、页面不自行请求 /records；
20. 详情内编号全部 chip（V/A/O/VR/VJ/EM/I 等），点击 openRecord 完整编号；
21. 导出成功：请求 #53（project_id+version）、下载链接 href/download、同源说明；
22. 导出失败：404 + 服务端 note 原文 + 下一步条件、失败不渲染下载链接；
23. 单版主体：列表/详情只有当前版本，无历史版本按钮；
24. 五分区整体缺失：每分区显式「—（未提供）」，不虚构 0；
25. 覆盖缺口取当前版本：浏览历史版本只改详情节，中栏覆盖不回退；
26. 阶段报告未携带覆盖块：显式「—（未提供）；未提供不代表已覆盖」；
27. 真实服务：manifest（order 60）+ 真实项目/漏洞 + #39/#40 读回 + refresh=1 版本推进 +
    真实详情（MR-）+ 真实导出（#53 返回 Markdown 200）；
28. 真实服务：未知报告编号 404 如实呈现（不泄露存在性）。
