## 2. 实现范围

- 端点（蓝图 §5 注册表编号）：
  - **#37 POST /sorne/worker-reports**：提交分层汇报。仅 worker 会话（蓝图 §8.2 worker 行含 #37），且只能汇报派给自己的 Attempt（worker_id === 会话 actor，C2 同法）；project_id/actor 以会话为准，信封内自报一律拒绝（§11.1）。事务内：幂等（§11.1 域，登记于 A1 submissions 表）→ Attempt/意图一致性 → replaces/base 存在性 → 时效边界 → 引用有效性 + 发现类型与库一致 + **状态以库为准**（§18.4/场景 27）→ 记录清单生成（§18.5-2「汇报工具生成本次记录清单」）→ **程序覆盖检查**（新漏洞/待验证线索/状态撤回/阻塞/unknown 调用必须列入交接卡结构化引用或 omitted_sections 显式分类清单，否则 PRECONDITION_INVALID 退回，场景 26）→ 汇报落库 + worker_report.submitted 事件 + 幂等回执**同一 runSerial 事务**（§18.5-3；§2 约束 10）。
  - **#38 GET /sorne/worker-reports/:id**：按层读取（§18.3 三层表）。`layer=handoff_card`（默认）：交接卡渲染，**可配置长度预算**（query `budget` 500..20000，默认 2000，环境变量 `SORNE_HANDOFF_BUDGET` 可覆盖默认）超预算**分组分页**（每组 ≤8 条切子组、页不越预算、单组自身超预算时整组保留不截断）+ `omitted_from_this_page`（type/count/read_pointer 显式展开入口）+ has_more/next_page（场景 28）；`layer=key_records`：关键记录层（发现/重要尝试/矛盾/未解决/阻塞/前提变化/显式省略清单 + 展开入口 + AI 建议单独标注）；`layer=full_basis`：完整依据层（记录清单明细：tool_calls/进展行/判断记录/撤回边内联呈现 + 读取入口：判断类→#14、capture→#44、blob→#43）。跨项目一律 404 不泄露存在性；无会话回环按 user 面只读（需显式 project_id，B1/C1/C2 先例）。C2 #25 写入同表的进展行（`WR-NNNN`，content.source=attempt_progress）以降级视图呈现并显式标注，互不干扰。
- 表/迁移（蓝图 §4）：只用冻结表 `worker_reports`、`report_receipts`（E1 写入侧）、`submissions`（幂等域复用）、`outbox`。**未新增迁移**。WorkerReport §18.3 合同的结构化列表（important_findings/material_conditions/contradictions/significant_attempts/unresolved_questions/blockers/prerequisite_changes/proposed_next_actions/evidence_refs/full_record_pointer）存 `worker_reports.content`（JSON），列名与 DDL 一一对应；服务端生成的记录清单存 `content.manifest`（`source_manifest_id` 列指向其编号 `WRM-<projectId>-NNNN`）。
- 事件（蓝图 §6 目录）：`worker_report.submitted`（提交同事务落 Outbox；payload：report_id/kind/intent_id/attempt_id/worker_id/source_manifest_id/source_commit_boundary/**covered_record_ids**（判断记录 + unknown 调用编号，供消费端按记录 ID 去重通知效果，§18.5 末段）/manifest_counts/omitted_types/replaces/base/newer_records_since_boundary）。
- 错误码（蓝图 §5.3 注册表内）：INVALID_REFERENCE（attempt/replaces/base/evidence_refs/finding 引用）、PRECONDITION_INVALID（覆盖检查退回，C2 完成建议同构先例）、STALE_STATE（状态声明与库不一致，场景 27）、IDEMPOTENCY_KEY_REUSED（同 ID 不同内容）、BAD_REQUEST（形状/类型声明/boundary 未来值）。授权拒绝复用传输层 TRUST_DENIED(403)（§20.1 十三码无授权类，A1/B2/C2/D1 先例）。
- 编号：汇报 `WR-<projectId>-NNNN`、清单 `WRM-<projectId>-NNNN`（带项目前缀规避 A1 编号序列跨项目主键冲突，C1/D1/D2 先例；与 C2 在 worker_reports 的 `WR-NNNN` 进展行共享同项目 `worker_report` 序列，同项目互斥递增、形态互不冲突）。

### 关键设计决策（供评审确认）

1. **执行窗口归因规则 v1**（记录清单如何圈定「本次记录」）：
   - tool_calls 与 C2 #25 进展行：`attempt_id` 列直接归因（精确）；
   - 判断类记录（V/H/F）与撤回边：冻结 DDL 该类表无 attempt 列，且 A1 `locateRecord` 不解析 `ATT-` 编号导致 `produced_by → attempt` 边无法经 #10 建立（A1 既有约束），故按「创建者 = attempt.worker_id 且 created_seq ∈ (lo, boundary]」归因。**保守并集**：同 worker 并行 attempt 的记录可能并入清单——覆盖检查宁可多要求列明（§18.4 的补充路径含显式分类清单），不漏报；
   - **增量汇报（base_report_id 存在）**：新增类对象（新漏洞/待验证/撤回）的窗口下界收缩到基线汇报的 source_commit_boundary（§18.6「新汇报默认强调相对于 base_report 的变化」），基线已覆盖的新增对象不再重复要求；**unknown 调用与 blocked 不收缩**（持续未决状态，§18.4 必须保留「实际未完成部分、工具失败、执行结果未知和阻塞原因」）；replaces（修正同一份汇报）不收缩。
2. **五类覆盖对象的库内判定**：新漏洞=窗口内 vulnerabilities；待验证线索=窗口内 hypotheses 且 status∈{open,testing}；状态撤回=窗口内 facts 当前 status∈{retracted,superseded} 或窗口内 retracts/supersedes 边（对象与其边均需列明）；阻塞=该 attempt 的 C2 blocked 进展行（本次汇报 kind=blocked 且 blockers 非空时视为本汇报已承载该语义——映射决策）；unknown=该 attempt status='unknown' 的 tool_calls。满足路径=结构化引用字段命中（record_id/ref/tool_call_id/attempt_id/report_id/relation_id/capture_id/evidence_ref；不解析自由文本）或 omitted_sections 对应 type（vulnerabilities/pending_leads/retractions/blockers/unknown_tool_calls，含泛型 key_records）且带 read_pointer。
3. **completion 语义边界**（§18.3「completion 仅表示 worker 对本次意图执行的完成汇报」）：E2 不改 intents/attempts 状态（意图完成判定归 C1 reviewCompletion、Attempt 终结归 C2 #25 完成建议），不自动确认漏洞、不结束项目；有对应用例锁定。
4. **manifest 无独立表**：冻结 DDL 无汇报记录清单表；清单本体持久化于汇报行 `content.manifest`（不可变：rule/boundary/counts/records/content_hash），`source_manifest_id` 列持编号。§18.4「程序根据 source_manifest 检查引用有效性」照常成立（检查在清单生成后进行）。
5. **时效**（§18.3 末段）：boundary 缺省取提交时刻已分配边界；声明未来值拒绝；老 boundary 之后已有新记录 → 不拒绝（「新发现可以在汇报生成期间继续提交，并由后续增量通知覆盖」），回执 `newer_records_since_boundary` + warnings 提示、读取面 `boundary` 块附 latest_commit_seq。
6. **幂等**：请求必填 `submission_id`（§11.1 幂等域，重试必须同 ID）；回执登记 submissions 表 → 重启后原回执仍可恢复（有重启用例）；同一汇报重复投递不重复落库、不重复发事件（有用例）；「不重复创建执行分配」以提交前后 attempts 行数不变 + 事件恰一条断言（E2 无创建分配的代码路径，程序保障面为幂等与事件去重）。
