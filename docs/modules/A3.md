  项目计数）；生命周期操作（暂停/停止/恢复 + §16.4 停止语义说明：禁止新派发、证据保留、
  恢复重查范围/前提/预算、局部目标可达成长期目标继续、waiting_for_change 非结束）；
  当前范围（§17 允许/拒绝（优先）/待判断三组，未配置显式提示、历史版本计数、条目只展示
  不改写）；新范围版本（本地 JSON 校验拦截、提交体带 project_id/rules/revision/summary、
  授权输入不落浏览器存储的说明）；项目目录布局（§5.2 视图 + 「逻辑路径不承担历史证据身份」
  等程序义务说明）。
- **未实现端点**：每张卡独立判定 501 → 「未实现」状态（标题 + 桩消息 + 负责模块标注），

## 5. 偏差与已知问题

1. **冻结 `client.js` 的 api() 对本工程错误信封丢失 message（第 1 轮打磨已修复）**：
   `client.js` 沿用 dsh-mrecon 的 `{error}` 信封假设，而本工程错误信封是
   `{code, message, retryable}`（lib/errors.mjs），非 2xx 时 `msg` 取到 `data.error`
   （undefined），用户看到的错误详情为空（显示为 "Error"）。**2026-11-05 第 1 轮打磨
   已按本条建议修正 client.js**（message 优先，兼容 `{error}` 字符串/对象两种旧形态，
   两者皆缺时退回 `HTTP <status>`；页面侧 `errMessage` 降级分支保留作防御），并在
   `test/ui-shell.test.mjs` 增补对 client.js 本体的直接用例（经 `__test__.api` 以真实
   HTTP 服务驱动）、同步更新 ui-shell/ui-maps 的 realApi 镜像为同构实现。修改冻结
   共享文件 client.js 未经架构师批准——按第 1 轮打磨任务指令执行并在此上报。
2. **页面有状态写法与骨架示例不同（无钩子 + React.Component 子类）**：冻结外壳在
   WorkbenchShell 渲染期同步调用 `page.render(ctx)`，页面若在 render 顶层调用 React
   钩子，钩子会注册到外壳组件上；外壳首帧 `pages=[]`、后续帧才有页面，钩子数跨渲染
   变化会被真实 React 判非法（"Rendered more hooks than during the previous render"）。
   骨架期 overview 页示例用的正是钩子写法，未经真实 React 验证。A3 页面改为：
   `render` 返回静态头 + 一个 `React.Component` 子类元素（外壳重渲染即重挂载，导航后
   状态重置符合工作台语义；基类取 `React.Component`，宿主未提供时退化为本地构造基类
   以兼容极简测试宿主）。已用仓库内 React 18 + react-dom/server 对类页模式做过 SSR
   实测（静态标题与类组件内容均渲染）。**建议架构师在蓝图 §2.6 补一句页面禁用钩子的
   约定**，B3/C3/D3/E3/F3 前端模块沿用本模式（A3 测试已把「无钩子」固化为契约用例 1）。
   注：施工期间骨架维护方在 smoke.test.mjs 增补了「页面模块（A3 起）允许以
   React.Component 类组件收敛有状态部分」的注记，与本实现一致。
3. **A1 端点响应形状未在蓝图冻结，A3 按已落地实装绑定**：#4–#9 的 JSON 形状由 A1
   实装决定，蓝图未规定。A3 按 2026-11-04 23:45 落地的 A1 形状绑定（列表 `{projects:[]}`、
   详情 `{project,scope,counts}` 包装、范围 `{current,configured,history,note}`、创建回执
