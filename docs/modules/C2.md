## 2. 实现范围

### 端点（蓝图 §5 注册表编号；全部替换 501 桩）

- **#22 POST /attempts**：创建执行分配 + 条件领取租约（runtime 角色）。同
  `assignment_id`+同 intent+同 worker 重发幂等返回原 Attempt（§16.2）；同分配不同
  内容 `IDEMPOTENCY_KEY_REUSED`；并发领取由部分唯一索引
  `idx_attempts_active_assignment` 兜底（跨进程亦受保护）；fencing token 自
  `id_sequences(project,'fencing')` 单调分配（DDL `UNIQUE(project_id,fencing_token)`
  兜底）。
- **#23 GET /attempts**：队列与租约视图（只读；任意有效会话 + 无会话回环按 user
  面只读，B1 快照端点同 precedent）。每 Attempt 附租约剩余秒数、`tool_calls`
  摘要（by_status/running/unknown/planned 明细）、汇报计数（unhandled）；游标分页
  `after`（`cursor` 为 UI 别名）/`next_after`/`has_more`；fencing_token 对
  user/无会话隐藏、worker 仅见本人、runtime/orchestrator/verifier 可见。
- **#24 POST /attempts/:id/lifecycle**：`heartbeat`（条件 UPDATE 三条件续租：token
  +状态+租约未过期；失败 `LEASE_EXPIRED` 带原因）/`suspend`（保存原因与恢复条件
  到 recovery_note，释放租约）/`resume`（重签租约；撞部分唯一索引 →
  `PRECONDITION_INVALID`）/`cancel`（running→unknown（外部结果未观测）、
  planned→cancelled，历史全保留）。
- **#25 POST /attempts/:id/progress**（§11.2 进展/阻塞/完成建议）：worker（本人
  Attempt）或 runtime。进展落 `worker_reports`（kind progress/blocked/completion，
  handling_status=pending 待协调面处理）；**迟到提交留档**（late 标记 + 来源 +
  late_reason，不改任何 Attempt 状态，响应明示「不再获得工具执行权限」）；
  完成建议在非迟到路径检查全部工具调用终态（unknown 须先 resolve）后把
  **Attempt** 置 completed——**不触碰 intents.status**（C1 语义域，见偏差 6）。
- **#26 POST /tool-calls**（工具网关）：动作 `register`（planned）/`start`
  （running，逐跳复检）/`complete`（succeeded/failed + evidence_refs 校验 +
  touched_targets 事后判定 + 幂等重复落定）/`mark_unknown`（进程中断未决）/
  `resolve`（unknown→succeeded/failed/cancelled，**必须携带 check_note**——先检查
  现状再决定重试的结构性前提）/`cancel`（执行者主动取消）。同身份
  （attempt+tool_name+args_digest）存在未决 unknown 时拒绝新登记
  （`PRECONDITION_INVALID`，§20.3 场景 18）。

### 错误码（蓝图 §5.3）

- `LEASE_EXPIRED`（过期/状态失效/fencing 不匹配；不可重试，next_requirements 指明
  迟到面仍可留档）、`PRECONDITION_INVALID`（前提失效/项目停止暂停/未终态完成/
  unknown 未决重试/恢复撞索引）、`SCOPE_DENIED`/`SCOPE_UNRESOLVED`（§17 三区与
  拒绝优先）、`RESOURCE_LIMIT`（统一并发上限 retryable=true；预算耗尽
  retryable=false）、`IDEMPOTENCY_KEY_REUSED`（同分配不同内容）、
  `INVALID_REFERENCE`（intent/资产/证据引用）、传输层 `TRUST_DENIED`（角色越权/
  非本人 Attempt/跨项目）沿用 A1/B2 先例。

### §17 范围判定（lib/store/scope.mjs）

- 版本化：每次判定读项目当前 `scope_revisions`；范围收缩立即影响新动作。
- 三区与优先级：**deny 任何命中即拒绝**（即使 allow/pending 也命中）→ 显式
  pending（压过通配 allow：用户明确标未决的目标不得被泛 allow 放行）→ allow →
  未列出（unlisted，同样按待判断处理）。未配置范围一律 `SCOPE_UNRESOLVED`
  （缺少目标范围不能默认任意目标可操作）。
- 条目形态：主机串（任意 scheme/端口）、`*.domain`（子域，不含裸域）、URL 串
  （约束 scheme+端口（缺省按 scheme 默认端口）+路径前缀）、对象
  `{host,scheme?,port?,path_prefix?}`（未给字段通配）。URL 条目不匹配裸主机目标
  （无法核实 scheme/端口 → 不放行）。
- 派发时：意图全部目标资产判定（deny→`SCOPE_DENIED`，pending→`SCOPE_UNRESOLVED`），
  `assets.scope_status` 以独立小事务回写（不随派发被拒回滚）；不可解析目标的资产
  放行并告警（动作层逐跳兜底）。
- 动作前：register/start 对调用声明/重申的全部目标逐个判定（§17「不能只检查最初
  提交的 URL」：多目标任一 deny 即整体拒绝；重定向目标作为新调用再过闸）。
- 已发出操作：complete 记录实际结果 + touched_targets 事后判定（非 allowed 的
  触达目标出警告与 `scope_violation_observed` 事件，不假装撤回）。
- 自报来源不参与判定：工具参数中的 `source_type=official` 等字段一律忽略。

### 执行前提（§9.2/§17，派发与动作前）

- 检查集 = 意图全部未撤回 `requires` 边端点 + `prerequisite_refs`（后者先做存在性
  校验 `INVALID_REFERENCE`）。
- 机器可判定谓词：requires_state 中的 `status=`/`review=`/`scope_status=`（其余
  文本为 AI 描述，程序不判定）；`scope_status=` 对资产前提按当前范围版本现算。
- 判断类前提的失效门槛（§8.2/§9.2）：hypotheses.rejected、facts.superseded/
  retracted、vulnerabilities.falsified → 阻止；vulnerabilities review=disputed →
  阻止；review=pending → 阻止（确认后新相关证据待复核，不能无条件放行，
  §20.3 场景 9 的执行面）。requires 边撤回后不再阻止。

### 执行态清扫（sweep；§10.2/§16.4/§18.2 步骤 3–4）

- 每个 C2 写操作与 #23 视图先执行：租约到期的活跃 Attempt → `interrupted`（running
  调用→unknown、planned→cancelled）+ `lease_expired` 通知；项目 stopped → 活跃
  Attempt `interrupted`（撤销执行权）+ `execution_revoked`（幂等；历史全保留）。
- 项目状态门槛：新派发/新工具动作（register/start）仅 active|waiting_for_change；
  paused 阻止新动作但允许心跳与在途落定；stopped 一律阻止新动作与心跳，落定
  （complete/resolve/mark_unknown）与迟到汇报仍允许（已发出操作记录实际结果，
  允许已产生证据被保存，§16.4）。
- 导出 `sweepExecutionState(pctx, projectId)` 供 F2 恢复流程（§18.2）调用。

### 子 agent 统一登记（§10.2）

- 子 agent 的建立与动作均为所属 Attempt 的工具调用（`tool_calls.created_by` 记
  执行 agent 身份，默认派发 worker）；继承同一租约/范围/前提/预算闸门，计入同一
  统一并发上限（默认 8，`resource_policy.max_running_tool_calls_per_attempt` 与
  `intents.budget.max_running_tool_calls` 可收紧取最小）；预算
  `intents.budget.max_tool_calls` 按 Attempt 计数（子 agent 同预算继承）。不得经
  子 agent 绕过调度服务另开无限执行链。

### §3.2 边界自查

- 程序侧只做：角色权限、必要前提、范围、资源上限、租约、fencing、幂等（分配/
  落定）、与 Outbox 同事务的可靠通知、状态机合法迁移。
- 不做：不自行重派（lease_expired 只通知 Orchestrator 决定）、不内置固定重试
  剧本（传输幂等由程序承担，测试策略重试由 AI 决定）、不解析 requires_state 的
  自由文本语义、不触碰 intents 状态机与漏洞状态（C1/D 阶段领域）、resolve 的
  check_note 只做结构性存在检查（核查语义质量属 AI/verifier）。

### 与蓝图的偏差（均已按「规范优先/如实记录」执行，未获架构师批准项标注 ★）

1. ★ **#25 进展记录落 `worker_reports` 表**：冻结 DDL 无 attempt 进展表，蓝图未
   规定 #25 的存储。选择 worker_reports（kind progress/blocked/completion 与
   §11.2「进展、阻塞、完成建议」天然对齐；handling_status=pending 进入 E1/E2 的
   待处理协调面；迟到标记存 content JSON）。代价：E2（阶段 E）实装 #37 时需识别
   C2 写入的行（content.source="attempt_progress" 区分）；已列协调项。
2. ★ **完成建议只终结 Attempt，不改 intents.status**：§10.1「程序检查必要产物和
   状态条件」的意图级判定属 C1（其竣工记录以存储级 API reviewCompletion 落地并
   明示「C2 并行期不 import」）。C2 的 #25 接受完成建议后置 Attempt=completed 并
   出 attempt_completed 事件；意图是否 resolved 由 C1/E1 面（或后续经 §2.7 新冻结
   签名）判定。双方均未越界，但「完成建议 → 意图 resolved」的贯通需架构师在
   D/E 阶段前裁决衔接方式（C1 偏差 5 同源）。
3. ★ **目标集重申契约**：冻结 DDL 的 tool_calls 仅有 args_digest（无 args 列），
   登记时派生的目标集无法从库行还原。契约：register 回执返回 declared_targets，
   执行运行时在 start 请求重申以完成逐跳复检；未重申时 gate.targets_recheck=
   "not_redeclared"（登记时已全量过闸；complete 的 touched_targets 事后判定兜底）。

### 未覆盖项 / 已知限制

- **暂停（paused）撤销边界**：paused 阻止新动作但保留心跳与在途落定（暂停不撤
  租约，恢复无需重派）；stopped 撤销执行权。若评审认为 paused 也应撤销执行权，
  需调整 sweep 的门槛集合（一行改动 + 用例）。
- **工具真实执行不在本模块**：#26 是网关（登记/校验/状态机），工具进程的实际
  拉起与取消信号传递属宿主运行时（dsh 侧），本模块以状态机与闸门承载其可靠语义
  （蓝图 §13 风险 3 的端点形态）。
- **IP/CIDR 目标仅精确匹配**：范围条目按主机字面匹配，未实现 CIDR 网段判定
  （需要时走 §12.5 变更流程扩展 scope.mjs 条目语义）。
- **并发上限/预算默认值**：统一并发默认 8（可经 resource_policy/intents.budget
  收紧）；max_tool_calls 预算默认不限（AI 显式设置才生效）。数值为程序侧资源
  保障默认，非探索策略（§3.2）。
