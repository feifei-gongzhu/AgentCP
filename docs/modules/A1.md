## 2. 实现范围

- 表/迁移（蓝图 §4）：0001（冻结 DDL，未改）；新增 0002 将 submissions 主键重建为

  id_sequences、submissions、outbox、assets、observations、hypotheses、vulnerabilities、
  relations、evidence_memberships（证据集成员/撤回，§12.1/§12.3 机制位）。
- 事件（蓝图 §6 目录）：`asset.discovered`、`observation.appended`、`hypothesis.proposed`
  （建立/修订）、`vulnerability.state_changed`（创建即 suspected）、`evidence_set.revised`、
  `scope.revised`、`dependency.changed`（requires 边新增/撤回，§9.2）、
  `resource_state.changed`（项目生命周期映射，见 §5 说明 3）、`relation.added`（见偏差 2）。
  事件与业务记录、提交回执同一 runSerial 事务写入（§2 约束 10/§13/§14.1）；
  commit_seq 事务内分配，同提交内 event_index 连续。
- 错误码（蓝图 §5.3）：INVALID_REFERENCE、IDEMPOTENCY_KEY_REUSED、STALE_STATE、
  PRECONDITION_INVALID（生命周期非法迁移/重复撤回）+ 传输层 TRUST_DENIED（鉴权）、
  BAD_REQUEST、NOT_FOUND、INTERNAL_ERROR。错误信封带 retryable / receipt / next_requirements。

实现要点（对照施工要求）：

- **runSerial 串行短事务全量落地**：项目/范围/生命周期/提交的全部写入经
  `record-service` → `db.mjs runSerial`，事务体同步，无跨事务 await（§5.1）。
- **submission_id 幂等**：同 `(project_id, submitter_id, submission_id)` + 相同请求摘要
  （canonicalJson→sha256）返回**原回执**（逐字段相同，含 result_hash）；同 ID 不同内容
  422 `IDEMPOTENCY_KEY_REUSED` 并带回原提交回执摘要，不覆盖原提交（§11.1）。
  幂等判定在事务内先于 commit_seq 分配，重放零副作用。
- **local_ref→正式 ID**：操作内引用先查本事务映射、再按正式编号解析；
  local_ref 禁用正式编号形态；回执返回 `ids` 映射（§11.1）。
- **commit_seq 事务内分配**：`projects.next_commit_seq` 事务内取出并推进；
  并发提交获得唯一连续序号（测试断言 [2..7] 连续）。
- **追加/修改分流（§11.3）**：append 类（register_asset/append_observation/
  propose_hypothesis/report_vulnerability/add_relation）不查节点状态版本；
  modify 类（revise_hypothesis/retract_relation）校验 expected 版本，不符 STALE_STATE；
  判断内容修改推进 claim_revision。逻辑依赖组全部成功或全部失败（注入测试验证整组回滚）。
- **证据集版本（§11.3/§12.1/§12.3）**：supports/contradicts 落到判断类对象
  （hypotheses/facts/vulnerabilities）时维护 evidence_memberships：新成员/立场变化
  → evidence_revision++（confirmed 且 review=clear 的漏洞置 review=pending，保留确认历史）；
  完全重复 → 去重告警，不推进版本、不触发复核；无关备注（无关系的观察）不推进任何
  判断对象的版本。
- **项目生命周期（§16.4）**：active/waiting_for_change/paused/stopped 四态 + 迁移表；
  非法迁移 PRECONDITION_INVALID；可选 expected_state_version（STALE_STATE）；
  stopped 下已产生证据的保存不被拒绝（禁止的是新派发，属 C2 派发侧）。
- **范围版本表（§17）**：scope_revisions 版本化（allow/deny/pending 数组形状校验），
  创建即更新 current_scope_revision 并发 scope.revised；无范围时 GET /scope 显式
  configured=false +「不得默认任意目标可操作」，范围判定/拒绝优先由 C2 在动作前执行。
- **会话与角色（§8）**：`sessions.mjs` 进程内签发（蓝图 §14 风险 3 首版决策），
  绑定 {project_id, actor, role}，请求头 `x-sorne-session` 承载，TTL 可选；
  签发不经任何 HTTP 端点。信封内自报 project_id/actor/role 一律 BAD_REQUEST 拒绝。
  #4–#9 为用户面（无会话按 user；非 user 会话 403）；#10 需 AI 面会话，
  操作级角色白名单（worker 目录：append_observation/propose_hypothesis/建 suspected
  漏洞/关系/资产登记/内容修订；确认类操作不在目录，worker 无法借提交确认漏洞）。
  后续模块经 `registerSubmissionOps(owner, ops)` 在自己文件内注册新操作，无需改本模块。
- **health 扩展**：db（可打开 + schema_version）、outbox（pending/sent/failed/skipped/total）、
  projects 计数、sessions 活跃数；存储检查失败时 ok=false 带原因。

## 5. 偏差与已知问题

- 与蓝图的偏差（原因 + 是否已报架构师批准）：
  1. **迁移 0002 重建 submissions 主键**：冻结 DDL 0001 中 `submissions.id TEXT PRIMARY KEY`
     为全局主键，使同一 submission_id 字符串跨项目、跨提交者全局互斥，超出规范
     §6.3/§11.1「(project_id, submitter_id, submission_id) 身份域」语义（不同 submitter
     应有独立幂等域）。按蓝图 §2.3 迁移路径新增 0002（新主键严格弱于旧约束，历史数据
     不可能违反，无需清洗；0001 本体未改）。**未经架构师批准——按「规范优先于蓝图」
     执行并在此上报**，若架构师要求回退，需同时接受「跨 submitter 同 ID 冲突」的替代语义。
  2. **新增事件类型 `relation.added`**：蓝图 §6 事件目录表格未列通用新边事件，但规范
     §15.5 明确要求「新边事件包含端点信息」（动态订阅依赖），且目录表自称收录
     「§14.1 必要事件全集 + 规范他处明确要求的事件」。未改蓝图，在此上报该目录表遗漏。
  3. 生命周期变化以 `resource_state.changed` 承载（payload.kind=project_lifecycle）：
     目录无专用项目状态事件，此为映射决策，非规范硬性要求，供评审确认。
  4. 授权拒绝（无会话/角色越权）复用传输层 TRUST_DENIED(403)：§20.1 的 13 码注册表
     （冻结于 lib/errors.mjs）无授权类错误码，未擅自扩表。
