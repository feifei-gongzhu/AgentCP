### 动作词表（程序可执行的操作语义面，§3.2 边界）

`assign_execution / suspend_execution / resume_execution / cancel_execution /
request_verification / request_planning / followup / attach_context / handle_report /
set_execution_limits / record_strategy`

- 前五类为**外部委托型**：调用 C2 `dispatchAttempt`/`attemptLifecycle` 与 D1
  `requestVerification` 的真实事务；重启核对时先以逐类谓词查**实际效果**（如
  assignment 句柄下已存在 Attempt、目标状态已达成），已完成的标记 `reconciled` 不重放；
- 后六类为**库内原子型**：效果（事件/回执/plan_run/限额/策略记录）与动作状态同一
  runSerial 事务提交，pending 即未发生，可安全执行；
- `record_strategy` 承载 §16.3「继续/追问/换方法/暂缓/重规划」词汇（strategy+理由+
  恢复条件），纯持久化无程序化流程语义——程序不写死任何重试流水线；
- `set_execution_limits` 落实「支持 AI 设并行限制」：写 projects.resource_policy.
  max_active_attempts（硬顶 64，RESOURCE_LIMIT 越界拒绝）并发 resource_state.changed
  事件，立即对 C2 派发面生效（测试实证第二个派发被 RESOURCE_LIMIT 拦截）。

### 错误码（蓝图 §5.3）

INVALID_REFERENCE（引用汇报/事件/意图/Attempt/记录不存在）、IDEMPOTENCY_KEY_REUSED

## 5. 偏差与已知问题

1. **单动作端点的受阻语义（#34/#35/#36）**：决定与动作已持久化但工具目的未达成时，
   端点以动作错误码抛出并携带 `receipt:{decision_id, action_id}`（§3.2 工具返回受阻
   原因 + §20.1 不得用错误掩盖已保存内容）。未报批，语义映射供评审。
2. **`assign_execution` 的分配句柄**：payload.assignment_id 缺省时以动作幂等键为
   assignment 句柄（使重启核对可按句柄查实际效果；C2 自身的同句柄幂等为第二道保障）。
   映射决策，未报批。
3. **`set_execution_limits` 写 projects.resource_policy（A1 域表）**：规范 §16.3 要求
   「支持 AI 设置方向预算与并行限制」；方向预算在 intents.budget（planner 经 #20 设置，
   面板供给展示），项目级并行上限无既有端点，E1 以协调动作落实现（1..64 硬顶）。
   跨域写表供架构师追认；如要求收编可改由 A1 出端点、E1 动作转调。
4. **规划请求/清扫不发 Outbox 事件**：蓝图 §6 目录无 plan.requested/plan.run.rejected
   类型（A1 已上报的目录遗漏同源）；planner 的唤醒经 Orchestrator 转交（§18.6）与
   overview/plan-requests 供给承载，不扩目录。
5. **overview 读取触发程序状态核对（含动作补执行）**：属程序自愈（§16.1 定期核对），
   B2 变化页读取标记 delivered 的同形先例；补执行的动作均为已持久化决定（orchestrator
   已决），非越权代决。供评审确认。
6. **handle_report 与 #33 的关系**：动作与独立端点共用同一回执落库函数；accepted/
   coordinated 的 handled 门控在两端一致（决定引用该汇报）。#33 支持自动回溯最近引用
   决定（带 warning），显式 decision_id 优先。
7. **request_verification 的重启核对**：无本地谓词，依赖 D1 §7.3 去重键（重放返回原
   job，deduplicated=true 随结果记录）；D1 幂等为真实保障，已在模块头文档化。
8. **`orchestration.decision_recorded` 复用为动作投递载体**（payload.kind 区分
   followup/context_attached/decision_recorded）：目录未提供动作级类型；与 A1 的
   resource_state.changed payload.kind 先例一致。
9. **E2 并行时序（如实记录）**：交付窗口内全量门禁一次 365/366（13:51），唯一失败位于
   并行施工中 E2 独占 test/worker-reports.test.mjs（其自身覆盖检查夹具，13:52 收敛
   20/20）；本模块 22 用例该期间连续全绿、与 E2 零 import 耦合，终态连续 3 次全量
   366/366 全绿。
10. **已知限制**：overview 的「重要发现/关键变化/供给」为有界清单（10/20/20 条上限 +
    has_more/计数），完整读取按编号经 #14/#16（§18.6 面板折叠不改变原始关系与恢复条件，
    panel_notes 已注明）；未处理汇报的 condition_gaps 从 worker_reports.content 提取
    （C2 进展汇报与 E2 分层汇报两种形态兼容）。
