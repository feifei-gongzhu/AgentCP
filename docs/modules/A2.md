## 2. 实现范围

- 端点（蓝图 §5 注册表编号）：
  - **#11 POST /sorne/evidence/blobs**（rawBody 流式上传）：staging（随机名临时文件
    + fsync）→ SHA-256 计算（可对照 `expected_sha256` 拒传输损坏）→ 固定到
    `evidence/blobs/sha256/<ab>/<hash>`（目标已存在则校验内容一致后去重，绝不覆盖）
    → `runSerial` 库事务登记 → 回执（哈希、byte_size、representation、
    `referencable: true`、`deduplicated`）。上限默认 64MiB（`SORNE_EVIDENCE_MAX_BYTES`
    覆盖），超限 413 且不留记录；存储不可用返回 retryable 错误并给出 next_requirements。
  - **#43 GET /sorne/evidence/blobs/{sha256}**：按哈希读原始证据字节（§8.3 验证读取、
    §18.3 完整依据层）。逐次校验磁盘内容哈希，不符拒绝提供（integrity=mismatch）；
    未固定/lost 拒绝（EVIDENCE_NOT_COMMITTED）；多项目同哈希要求 `?project_id=` 消歧
    （存储权限域=项目）。
  - **#12 POST /sorne/captures**（§5.3 Capture 合同）：校验（项目/Blob/资源/Attempt
    存在性、Blob 必须 fixed、表示形式枚举、source_kind 枚举、observed_at ISO）→
    采集前磁盘完整性核实（缺失/损坏标记 Blob `lost` 并拒绝，不造假记录）→
    同一事务内登记 Capture + `capture.completed` Outbox 事件（同 URL 新版本内容时
    同事务追加 `resource.content_changed`，§14.1）→ 回执（capture_no、commit_seq、
    event_id）。幂等：同 `(project_id, tool_call_id)` 同内容返回原采集；同 ID 不同
    内容 `IDEMPOTENCY_KEY_REUSED`。提交后尽力物化 assets/ 逻辑入口（视图失败不影响
    事实）。
  - **#44 GET /sorne/captures/{id}**（§18.3 完整依据层）：采集全字段 + 响应体/请求
    记录/响应头三个 Blob 的解析视图（sha256、representation、storage_status、读取
    入口）+ 派生链（transforms）+ read_pointers。
- 表/迁移（蓝图 §4）：无新迁移；使用 0001 冻结 DDL 的 `blobs`、`captures`、
  `transforms`、`outbox`、`id_sequences`、`projects`。编号：`B-<project_id>-NNNN` /
  `CAP-<project_id>-NNNN`（id_sequences 项目内序列 + 项目编号前缀保证全局 PK 唯一）。
- 事件（蓝图 §6 目录）：`capture.completed`（登记完成）、`resource.content_changed`
  （同 URL 新版本内容，§14.1「相关内容变化」）。Blob 上传本身不产生事件（§14.1
  必要事件集不含 Blob 级事件）。
- 错误码（蓝图 §5.3）：`INVALID_REFERENCE`（未知项目/Blob/资源/Attempt、锚点绑定
  不符）、`EVIDENCE_NOT_COMMITTED`（引用未固定/lost、采集前证据文件缺失或损坏）、
  `IDEMPOTENCY_KEY_REUSED`（同 tool_call_id 不同内容）；传输层 `BAD_REQUEST`（参数/
  锚点形状）、`REQUEST_TOO_LARGE`（超上限）、`NOT_FOUND`、`INTERNAL_ERROR`
  （存储不可用 retryable=true、完整性不符 retryable=false）。
- 存储级 API（供后续阶段）：`storeBlob/stageBytes/fixBlobFile/registerBlob`
  （§13 分步编排，C2 工具网关与 F2 恢复复用）、`registerTransform`（§5.3 派生链五
  元组，derived Blob 强制 representation=derived）、`resolveEvidenceAnchor`/
  `validateEvidenceAnchorShape`（§5.4，供 A1 observations 锚点校验与 D1 验证读取）、
  `findStorageAnomalies`（孤立 Blob/缺失/损坏盘点）、`verifyBlobIntegrity`、
  `readBlobBytes`；layout：`materializeAssetEntry`/`rebuildAssetEntries`/
  `ensureWorkspace`/`safeSegment`/`projectDir`/`stateDbPath`/`evidenceDirs`/`blobPath`。

## 3. 验证

- 新增测试文件与用例清单（test/evidence.test.mjs，23 用例）：
  1. POST /evidence/blobs：staging→哈希→固定→登记→回执全链路（§13）
  2. rawBody 流式上传不受 256KiB JSON 预读上限约束（蓝图 §2.2/#11）
  3. 超过自定上限返回 413 REQUEST_TOO_LARGE 且不留任何记录
  4. 内容寻址去重：相同字节返回原回执，库中只有一行，去重不删采集历史
  5. representation 必填且受枚举约束；expected_sha256 不符拒绝且丢弃暂存
  6. **§20.3 场景 25（主责）**：证据存储不可用 → 可重试错误、不创建成功记录、工作明确受阻（真实注入：staging 被文件占据；恢复后受阻可解除）
  7. 不可变保护：目标 Blob 路径被不同内容占用时拒绝覆盖（真实损坏注入）
  8. GET /evidence/blobs/{sha256}：原始字节 + 元数据头；404/坏哈希/lost 拒读
  9. 磁盘内容与登记哈希不符时拒绝提供字节（完整性校验不静默；真实损坏注入）
  10. **§20.3 场景 4（主责）**：同 URL JS 内容变化 → 两个版本保留，旧行号锚点仍可读取（含 resource.content_changed 同事务事件与旧锚点错绑新版本被拒）
  11. **§20.3 场景 5（主责）**：两次响应仅 Token 不同 → 两份原始证据仍在，派生脱敏可降噪（registerTransform 派生链；同形降噪产物内容寻址去重）
  12. **§20.3 场景 23（主责）**：Blob 固定成功但事务失败 → 无半条引用，孤立 Blob 可识别（真实注入：事务内外键失效）
  13. POST /captures：校验、幂等（同 ID 原回执/不同内容拒绝）、同事务事件与回执（§5.3）
  14. POST /captures 引用校验：未固定 Blob 拒绝（EVIDENCE_NOT_COMMITTED）；未知对象拒绝（INVALID_REFERENCE）
  15. 第三方导入/worker 上传标记来源，不伪装为 tool_gateway（§5.3）
  16. 采集前证据文件缺失：标记 lost 并拒绝新采集引用（不造假记录；真实注入：删除文件）
  17. GET /captures/{id}：完整依据层详情与派生链、读取入口（§18.3）
  18. assets/ 逻辑目录：非法字符与路径穿越防护；逻辑路径不承担证据身份（§5.2）
  19. assets/ 逻辑目录：URL 冲突以资源编号消歧；最新入口标明采集编号并保留版本历史（§5.2）
  20. work/<intent>/<attempt>/ 工作区：创建成功且穿越段被中和（§5.2）
  21. EvidenceAnchor：表示形式绑定强校验；格式化产物的行号绑定派生 Blob（§5.4；line/byte/json_pointer/whole 四类定位符）
  22. 多项目隔离：同哈希双项目两行；读取需 project_id 消歧（存储权限域=项目）
  23. 重启恢复语义：句柄真实重开后证据、采集、锚点仍可读（§18.2 第 1 步的存储面）

## 5. 偏差与已知问题

- 与蓝图的偏差（原因 + 是否已报架构师批准）：
  1. **多项目布局解释**：蓝图 §1.1 的「项目目录按 §5.2 布局（含 state/）」在多项目
     单库（DDL 为多项目表结构）下取如下解释——共享库位于 `<dataDir>/state/sorne.sqlite`
     （与骨架冒烟测试一致），每个项目文件树位于 `<dataDir>/projects/<目录名>/`
     （evidence/assets/maps/reports/work）。A1 的 record-service.mjs 独立收敛到同一库
     路径，实际无冲突。**未报批**（规范 §5.2 明示目录命名为建议选型；如架构师认定
     需按项目分库，仅需调整 layout.stateDbPath 一处）。
  2. **transforms 无独立端点**：蓝图 44 端点清单不含 POST /transforms，故以存储级
     API（`registerTransform`）提供派生链登记（场景 5 的派生降噪经此验证）；D/F 阶段
     若需端点化，走 §12.5 变更流程。**未报批**（未越出清单新增端点）。
  3. **actor 来源为过渡方案**：`created_by` 取请求头 `x-sorne-actor`（缺省 unknown）。
     A1 已交付会话服务（`x-sorne-session`），但 sessions.mjs 不在蓝图 §2.7 冻结签名
     清单内，同阶段并行模块不得跨模块 import，故未接入。**已列为本记录协调项**：
     建议架构师将「会话解析」纳入 §2.7 或指示 A2 在阶段验收时切换（端点侧仅一处
     headerString 调用）。
  4. **数据库句柄记忆在 A2 内部**：lib/db.mjs（冻结）仅对并发 open 单飞，顺序 open
     会产生各自串行队列；A2 在 evidence.mjs 按路径记忆句柄保证模块内单队列。A1 有
     其独立 storeCache，跨模块两队列写同一库由 BEGIN IMMEDIATE + busy_timeout=5000
     串行化保障（85 用例含双模块并发场景全绿）。如需进程级单队列，应在冻结的
     lib/db.mjs 层统一（架构师变更）。**未报批**。
- 未覆盖项 / 已知限制：
  - 证据字节在内存缓冲（单 Blob 上限 64MiB，`SORNE_EVIDENCE_MAX_BYTES` 可调）；
    超大证据的分块/断点上传未做。
  - assets/ 逻辑入口为 Blob 字节副本（人可浏览视图），可能包含敏感内容；§5.3
    「秘密值受控引用」的完整机制由条件快照引用与后续模块（脱敏 transform）承担。
  - assets/ 物化为尽力而为：失败仅告警不回滚事实，可经 `rebuildAssetEntries` 从
    captures+blobs 完全重建（§5.2 视图可重建原则）。
  - 未建档资源（无 resource_id）的消歧键为确定性 URL 哈希 `u<8hex>`；A1 资源建档
    落地后自然使用真实资源编号。
  - GET blob 每次读盘哈希校验，超大 Blob 读取有 O(n) 开销（首版取舍：宁可慢不可
    静默提供损坏证据）。
- 留给后续阶段的接口预留：
  - C2 工具网关：`stageBytes/fixBlobFile/registerBlob` 分步 API（工具执行中即时
    固化证据）；F2 恢复：`findStorageAnomalies`（§18.2 第 1 步「检查已引用证据的
    可访问性和待固定上传」）、`verifyBlobIntegrity`。
  - A1 observations：`validateEvidenceAnchorShape` + `resolveEvidenceAnchor`
    （§5.4 锚点入 Observations.anchor 前的绑定校验）。
  - D1 验证：`GET /evidence/blobs/{sha256}`、`GET /captures/{id}`（§8.3 验证读取
    原始证据的既定落点）。
