## 2. 怎样安装进 dsh

以下步骤依据蓝图 §10（`docs/BLUEPRINT.md:559-588`）与本人实读的 `package.json`、`index.js`、`docs/modules/AGENTS.md`：

1. **前置**：Node ≥ 22.5（`package.json` engines）；dsh（DeepSeek Harness）桌面版或本地宿主；对等依赖 `@deepseek-ai/cordis ^4.0.1`、`@deepseek-ai/dsh-host-webserver ^0.1.0-rc.7 || ^0.2.0-rc.2`。
2. **接入插件**（二选一，以所用 dsh 版本的实际机制为准）：
   - 开发链接：在 dsh 的插件/市场配置中指向本目录（参考实现的 sourceSpec 布局为 `link:<插件绝对路径>`，安装后由 generation 清单反解）；
   - 或打包发布到 dsh 市场后安装。
3. **重启 dsh**：插件半端 `index.js` 的 `apply()` 在宿主启动时向 webServer 注册 `/sorne` 前缀路由并自动扫描装载 `lib/routes/*.routes.mjs`（`index.js:36-78`）；改 `package.json` 需重装/重启。
4. **客户端半端**：`package.json` 已声明 `dsh.client.inject: ["@deepseek-ai/dsh-client-runtime"]`（platform: web），dsh web 平台加载 `client.js` 注入运行时；工作台出现在设置区「Sorne 持续探索工作台」（使用 settings.section 插槽，蓝图 §13.2）。
5. **数据目录**：默认 `~/.sorne`，可用环境变量 `SORNE_DATA_DIR` 覆盖（`index.js:31-34`）。项目文件树按规范 §5.2 布局，共享单库 `state/sorne.sqlite`。
6. **AI 半端（可选但推荐）**：设置 `SORNE_LLM_BASE_URL`、`SORNE_LLM_MODEL`（可选 `SORNE_LLM_API_KEY`、`SORNE_LLM_TIMEOUT_MS`、`SORNE_AGENT_TICK_MS`）指向 OpenAI 兼容提供方；**未配置时代理运行时不启动（`started:false` + 原因日志），存储与全部端点不受影响，系统不会伪造 AI 决策**（`index.js:55-64`、`docs/modules/AGENTS.md` §2）。
7. **安装后自检**：浏览器访问 dsh 宿主的 `/sorne/health` 应返回 ok（含 db/schema/outbox 检查）；无真实 dsh 时可用第 8 条的测试宿主走查。
8. **无真实 dsh 的 UI 走查（冻结命令）**：
   ```bash
   npm i --no-save react@18 react-dom@18   # 仅为测试宿主提供 React UMD，不进依赖树
   npm run ui                                # http://127.0.0.1:8898/
   ```
   宿主行为：mock ctx 调真实 `apply()` 挂 `/sorne/*`；`/` 页面以 `__ModuleLoader__` shim + React UMD 渲染真实 `client.js` 外壳与全部页面（蓝图 §10.2）。终审验收已实测该宿主：`GET /` 200、`/react.js` 200、`/sorne/ui/manifest` 返回 10 页面、`/sorne/health` 200。
9. **开发门禁**：`npm test`（= `node --check` 全源文件 + `node --test "test/*.test.mjs"`；注意 Node 22.23.2 需带引号 glob，蓝图 §13.1）。

> ⚠️ 重要提醒：以上第 2–4 步的宿主机制（插槽清单、ModuleLoader 细节、sourceSpec 布局）是从 dsh-mrecon 参考实现**推断**的，本次交付未在真实 dsh 宿主上加载验证（蓝图 §14.1 已列为头号风险；详见本报告 §5.1）。首次真实接入可能需要对冻结文件做少量调整，届时走蓝图 §12.5 变更流程。

### 5.2 AI 决策环节未被真实 LLM 驱动

- 无 `SORNE_LLM_*` 配置时四角色循环正确进入显式等待、不伪造决策（不把 Orchestrator 降为固定流程引擎是规范 §3.1 明令）；模型传输层已用本地 OpenAI 兼容服务器补测（真实 fetch、鉴权头、超时、归一化，`docs/modules/AGENTS.md` §5.7）。

### 5.4 低优先级遗留清单（终审 197 项核对后的 16 项，均不阻塞验收）

依据任务提供的终审遗留清单，按类概括（逐条原文见该清单）：

1. **§6.1 通用字段字面偏差（6 项）**：submissions 无 `created_by/created_seq` 字面列（以 `submitter_id/commit_idx` 语义代位，规范 §6.3/§11.1 自身即用 submitter_id 命名）；worker_reports/plan_revisions/evidence_memberships/blobs/tool_calls+orchestration_actions 若干状态会迁移的列无 `updated_seq/state_version` 字面列（写路径均在串行事务内、或以条件 UPDATE/fencing/证据集版本代位，实际丢更新风险极低）。属规范措辞与冻结 DDL 的低危偏差。
2. **UI 呈现类（5 项）**：总览页两个语义不同的 `schema_version`（数据库迁移版本 4 与指标信封版本 1）同屏同名裸键并排，易读成自相矛盾；指标以原始 JSON 直出而非摘要卡；探索地图页部分结构键未中文化、空折叠块渲染噪音文案；范围历史计数把当前版本计入「历史 N 个」（恒 +1）；验证队列/漏洞台账/执行队列/报告列表游标耗尽后无「已全部加载」末尾标识（不构成静默截断，但无法区分「恰好读完」与「加载失败」）。
3. **交互纪律类（3 项）**：在途请求不中止（`api()` 无 AbortController 通道；跨项目竞态有防护，同项目内筛选/重置竞态静态核对确认存在、本地响应快未能稳定复现错乱）；生命周期按钮对当前状态不适用的操作未禁用（靠 422 反馈兜底）；外壳导航切换整树重挂载导致跨页展开态/分页位置丢失（蓝图记录的设计取舍，与跨页追溯可用性有张力）。
4. **外观性保留决策（1 项）**：所有编号首值从 2 起（PRJ-0002/A-0002…，1 号永不发放）；编号唯一性/稳定性不受影响，终审视核后保留（改动会使存量编号错位且无规范收益，`docs/modules/A1.md` 偏差 7）。
5. **证据缺口（1 项）**：即 §5.3 第 3 条错误边界无测试证据。

### 5.5 架构与运行环境风险（蓝图 §14 在案）

- `node:sqlite` 为实验特性（Node 22.23.2 验证可用，引擎锁定 ≥22.5）；SQLite 单机串行写满足规范 §5.1 首版，多实例部署需重新评估。
- 会话为进程内注册表（蓝图 §14.3 的首版决策），进程重启后由运行时重签，持久对象身份不受影响。
- §22 待实施评审配置（历史迁移、部署形态、验证策略细节、并发与预算参数、资产类型与规范化迁移、用户展示入口）尚未落定——验证策略注册表当前无内置策略，程序只校验注册与检查覆盖。
